# 400AF 方块渲染踩坑记录

这份文件记录已经在实机上验证过、或踩过坑的结论，避免重复试错。

---

## 1. OBJ 材质名必须是 `t0`

**症状**：方块贴图全黑，边缘出现品红色（missing texture 色）。

**原因**：Blockbench 导出 OBJ 时，`usemtl` 用的是随机 UUID 材质名
（例如 `usemtl m_ee737483-db08-44eb-0cc1-2e7d85072985`）。
NeoForge 的 `neoforge:obj` 加载器按**材质名精确匹配**模型 JSON 里的 `textures` 键，
UUID 名对不上任何键，于是贴图绑定失败。

**修法**（参照 HeXie）：

```
# .obj
mtllib <名字>.mtl
usemtl t0

# .mtl
newmtl t0
map_Kd #t0
Kd 1 1 1
d 1

// 模型 JSON
"textures": { "t0": "af400:block/<贴图>" }
```

`map_Kd #t0` 里的 `#t0` 是占位，真正路径由模型 JSON 的 `textures.t0` 提供。

## 2. 半透明窗户要用 composite 拆成两层

**症状**：窗户本身是半透明贴图（本模型 `A=130`），但游戏里显示为**纯黑**。

**原因**：`render_type: minecraft:cutout` 只区分「全透 / 全不透」，
中间 alpha 会被当作完全不透明渲染。即使改成 `translucent`，
同一模型里混着不透明车体和半透明窗户，也会出现排序/深度问题。

**修法**（参照 HeXie）：用 `neoforge:composite` 拆成两个子模型

```
af400_panel_small_window.json          ← composite，children = body + glass
af400_panel_small_window_body.json     ← render_type: minecraft:cutout，79 个面
af400_panel_small_window_glass.json    ← render_type: minecraft:translucent，2 个面
```

拆分脚本：[`tools/split-obj.ps1`](../tools/split-obj.ps1)
判定口径：面的 UV 落在窗户矩形内（u 0..0.1875, v 0.4375..0.5664）即归 glass。

> ⚠️ 若贴图改版导致窗户 UV 区域变化，必须同步更新 `split-obj.ps1` 的默认参数。

## 3. `getRenderShape` 用 `PART == 0 ? MODEL : INVISIBLE`

**已经踩过的坑**：为了让占位格「能被打掉」，曾把所有格都返回 `MODEL`
（靠 `empty.json` 隐藏）。结果 **composite 模型的玻璃层被破坏，窗户又变黑**。

**结论**：保持 HeXie 的原做法 —— 只有 PART=0 渲染，其余 `INVISIBLE`。
占位格的破坏靠 `onRemove` 连带处理，不依赖它自己被准心选中。

> 反例留档：`return RenderShape.MODEL;`（无条件）→ 窗户变黑。不要再用。

## 4. `rootOf` 反推主体不能直接减世界 X

**症状**：朝某些方向放置时，部件的部分格子没有碰撞。

**原因**：`offsetOf(part)` 返回的 X 分量表示「沿 facing 右方第几列」，
不是世界坐标的 X。facing 为 EAST/WEST 时右方是 ±Z 轴，
直接 `pos.offset(-col, ...)` 会反推出错误位置。

**修法**：

```java
return pos.relative(facing.getClockWise(), -col).below(row);
```

---

## 5. blockstate 变体数 = 4 朝向 × 16 part

`PART` 是 `IntegerProperty.create("part", 0, 15)`，所以每个朝向要写 16 个变体，
共 64 个。少了会在日志里刷：

```
missing model for variant: 'af400:af400_panel_small_window#facing=east,part=9'
```

## 6. 手工构建（本机网络受限时）

`maven.neoforged.net` 在本机不可达，`neoform-runtime:1.0.5` 拉不到，
ModDevGradle 无法完成 `createArtifactManifest`。

现有绕法：[`tools/build-manual.ps1`](../tools/build-manual.ps1)
用 `~/.gradle/caches/neoformruntime` 里已有的 `compiledWithNeoForge` 产物当 classpath，
直接 javac + 手工打包。第三方 mod（Create / Ponder）从 mods 目录取 jar。

> 这不是标准构建，只用于本机验证。CI 上走正常 Gradle。
